# Proposed implementation: Unicode identifier policy lab

Tier 3 bounded security-learning tool. Stages 1–5 approved by coordinator October 5 02:49; scope/addendum recorded in STATE.md. Use installed standard-library CPython, zero new spending and no external systems. RESEARCH.md records source review and alternatives. Sole writer stays this chat.

## Success criteria and scope

A reproducible offline CLI accepts a small synthetic JSON batch, preserves originals, shows each ordered transformation in escaped text and code points, and reports exact duplicates separately from distinct originals whose final keys coincide. A user can explain why NFC, compatibility normalization and full case folding produce different groups, and why none proves visual identity, authenticity or account safety.

No real usernames, passwords, accounts or domains; registration/authentication, IDNA/email/path/network transformations, real data collection and remote lookups are excluded. No visual-confusable implementation, production identifier grammar, locale tailoring, accent removal, whitespace trimming or format-control deletion. No UI/server, third-party runtime dependency, Unicode-table execution, publication, push, merge, new chat/scheduler/subagent or shared-tool changes. Documentation may compare visual-confusable alternatives without emitting a visual-security verdict.

## Frozen proposed contract

Input envelope has exactly schema, policy, items. schema uses ASCII [A-Za-z0-9/_-]{1,64}; known schema is unicode-policy-lab/1. policy uses ASCII [A-Za-z0-9_-]{1,64}; known labels below. items is a list of 0..16 exact objects with label and value only. Labels are unique ASCII [A-Za-z0-9_-]{1,32}; values are strings. No numeric tokens, booleans, null, extra/duplicate JSON fields or type coercion. Unknown finite schema/policy is unsupported only after full common-envelope/record validation; this does not validate unknown-profile semantics.

Strict UTF-8, no BOM/nonfinite/invalid JSON; bound file bytes to 16 KiB and JSON container depth to 4 before recursive parsing. Every decoded value is <=64 Unicode scalar values and <=256 UTF-8 bytes; totals <=1024 scalars/4096 bytes. Reject surrogates and noncharacters. Empty, controls, formatting, whitespace, unassigned and private-use scalars are deliberately admitted as teaching strings, not valid accounts. Escape them in output and do not silently delete them. Labels/unknown profile fields use the stated ASCII grammar, not Unicode \w. Direct API exact built-in types and iterative record/string bounds apply the same finite schema: containers at scalar fields or record/list positions are rejected before recursive traversal, so cyclic containers cannot be admitted.

Three named policies, each tied to versioned lab schema:

| Policy | Ordered operations | Equality |
|---|---|---|
| exact-v1 | retain original | identical scalar sequence |
| nfc-v1 | NFC(original) | identical normalized scalar sequence |
| nfkc-casefold-nfkc-v1 | NFKC(original), Python default full str.casefold(), NFKC(folded) | identical final scalar sequence |

No locale-specific T mapping. The third policy is our explicit teaching profile, not official toNFKC_Casefold. Originals and each intermediate stage are retained, even when a stage is unchanged. Check each intermediate result <=256 scalars/1024 UTF-8 bytes; bound each stage's batch totals <=4096 scalars/16384 bytes. Over-expansion is an explicit limit error with no partial equality/collision result. Small initial input bounds constrain the transformation work; post-step caps do not claim zero temporary allocation or a hostile-runtime memory sandbox.

Runtime contract: CPython 3.13.x and unicodedata 15.1.0, with installed 3.13.7 as the first verified patch. Other versions/implementations are unsupported, including exact-v1 so outputs never silently mix runtime contracts. Record actual implementation/Python/UCD versions. Source-backed shared-table version evidence is in RESEARCH.md; verify selected folding/normalization vectors and report other-patch coverage honestly. Do not claim a runtime metadata field separately exposes str.casefold's data version.

Validate the complete admitted document before runtime/profile decisions. Then transform every item within all bounds before grouping. No early 'equal' shortcut can hide a malformed last record. Final keys are compared by exact scalar equality. Deterministic groups retain first-occurrence ordering and all input labels/indices. exact_duplicates groups repeated original strings. induced_collisions groups final keys that contain >=2 distinct original strings, retaining any repeated members; include distinct-original counts. A batch with repeated identical originals only has no induced collision. Arrays/input order are evidence, not sorted away. Policy-induced grouping does not prove one real entity.

Output ASCII escaped JSON only, <=512 KiB, with schema/policy/runtime, original and stage evidence, grouping, limits and fixed assumptions. Code points use U+XXXX with longer hex for supplementary scalars; scalar counts differ from grapheme/display width. Reports are reversible synthetic text, not redacted/private-safe. Raw JSON spelling need not be reproduced; source input file is preserved and decoded originals/code points are never rewritten. No authentication/hash authority claim. CLI exit 0 complete/no induced collision, 1 complete/induced collision, 2 invalid/limit/I-O/delivery error, 3 unsupported profile/runtime. Error outputs contain bounded structural diagnostics, not arbitrary raw exception text. Output failure overrides an analysis success status.

Regular bounded file reading with pre/post metadata checks; no directory/pipe input. If an output path is offered, exclusive creation and input-alias checks; never overwrite input or existing output. Handle short writes, flush/close errors and actual closed-pipe stdout. No atomic stdout or hostile-filesystem-race guarantee; a failed newly created output may contain partial bytes and must not be treated as complete. Serialize/check size before emission. If output cap is unreachable under tighter shape limits, demonstrate the bound and test only the reachable seam, without claiming an oversized admitted document.

## Architecture and threat model

Strict admission -> version/profile guard -> ordered transformation with evidence -> grouping -> bounded serializer/delivery. Small stdlib modules plus unittest fixtures, CLI and demo. Original work; source excerpts retained separately with Unicode notice and byte/hash provenance. Inspect reused trusted decoding/I-O patterns, do not couple runtimes across labs.

Threats: malformed/ambiguous JSON, Unicode evidence loss, expansion, version drift, silent compatibility/default-ignorable policy, duplicate misclassification, terminal/control injection, error-path partial verdicts and file alias/output failures. Mitigations are exact schema/types, whole-document bounds, explicit stage names, escaped evidence, independent known answers, deterministic complete grouping and delivery checks. No malicious-package execution or live account changes. Unicode/collision observations cannot establish authorization, spoof resistance, database uniqueness or authenticity. Unassigned/format/private-use admission is pedagogical and not a universal policy recommendation.

## Stages and definitions of done

1. **Freeze contract and independent oracles.** Implement only after approval. Save source/license receipt before adaptation; select normalization columns and C/F folding rows with exact code-point expected answers. Fixtures cover canonical combining order/composition, compatibility fullwidth/ligature, sharp-s and dotted-I expansion, sigma, default-ignorable preservation, supplementary text and Latin/Cyrillic unequal comparison. Manually reviewed end-to-end expected stages/groups must not be computed from the implementation. Define genuine order-sensitive examples; do not assume stage removal is detectable without a discriminating input.
2. **One complete API slice.** Admission, version guards, all three policies, evidence and duplicate/collision groups. Tests cover the last-record invalid case, unknown profile with malformed data, empty/duplicates-only/distinct-key cases, scalar versus byte and step limits, custom/cyclic API input, and unchanged original evidence. No assert-based runtime validation. Passing focused normal tests marks this stage done.
3. **CLI and bounded demo.** Offline fixtures and deterministic expected output, all exit statuses, real stdout delivery behavior, file aliases/exclusive output, read/write/flush/close failures. Synthetic demo cases explain policy differences with code-point evidence. No rendering step or real identifier data. Test actual closed-pipe output rather than only mocks.
4. **Verification and review.** Normal and python -O suites (including optimized children), compile checks, installed Bandit with no broad suppressions, ECC self-review of actual code/callers/tests and fixes with affected reruns. At least three isolated meaningful mutants must fail assertions, not merely syntax errors/crashes: fold replaced with lower; NFKC replaced by NFC; collision distinct-original test removed; optionally provenance/original preservation or reachable bound weakened. Stage-order mutant only if independent vector distinguishes it. Preserve source unchanged across temporary mutants. Provenance tamper rejection and repaired invalid cases required. No independent-review or upstream/hosted assurance claim.
5. **Portfolio records and handoff.** README with setup/demo/architecture/security/limits/test evidence/learning; MIT original-code license, Unicode notices/attribution, AI-assistance disclosure, STATE/DECISIONS/LEARNING/REVIEW/VALIDATION and source/test/fixture hash receipt. Save relevant vault milestone via approved file access, or pending note if blocked. Local Git/CI preparation only if implementation approval expressly includes isolated repository initialization; owned-repository security baseline then applies, no hosted execution/publication assumed. Report exact evidence and remaining runtime/platform limits.

Sequence is dependency-ordered; each stage has focused checks. A source/provenance blocker or runtime mismatch must be resolved rather than silently switching versions, workers or dependencies. Maintain state when consequential facts change. Learning exercise is optional: explain a collision from original and intermediate code points, then identify an unequal pair whose glyphs may still be confusable.
